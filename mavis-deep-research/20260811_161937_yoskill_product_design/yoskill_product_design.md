# yo-skill 产品设计（V2）

**调研日期**：2026-08-11（V1 同日定稿，V2 同日按用户方向修正修订）
**修订说明**：V2 在用户明确的三点方向上深化——① 像 cc-switch 一样自动识别本机已装 Agent，并能安装/更新 Agent 本身；② 自动检测各 Agent 的 Skill/MCP，**收拢到保险库统一管理 + 重复项检测合并**；③ 商店升级为 **SkillHub 式分类仓库**。
**文档目的**：把"小白化、一键操作、简单明了"从口号落成可执行的产品设计——信息架构、用户旅程、界面定义、交互清单
**立场**：敢下判断、每个决策给出竞品依据；与已冻结结论（命名 / 隐喻 / 视觉 / 技术栈）保持一致
**输入材料**：竞品 UX 调研三份【1】【2】【3】+ cc-switch 同栈实战对标【4】+ 品牌定稿【5】+ 既有冻结结论【6】+ SkillHub 类市场实证【7】

---

## 一、设计总则：三条铁律

整个设计只服从三条铁律，任何功能提案与之冲突时以铁律为准。

**铁律 1：一键闭环。** 用户发起的每个意图（装一个 Skill、换台电脑、更新一个 Agent、合并重复项）都必须能用**一次点击**完成，且点击后产品负责兜底（装依赖、写配置、重启 Agent 提示）。竞品调研显示，"复制 JSON → 找配置文件 → 粘贴 → 重启"的四段式是小白流失的重灾区【1】；做到真一键的只有两类：GUI 表单代替 JSON（MCPHub Desktop）和 deeplink 唤起（ChatWise、Raycast、cc-switch）【1】【2】【4】。yo-skill 两者都要。

**铁律 2：隐喻降维。** 界面上**禁止出现** Skill、MCP、server、JSON、env、path 这些词。统一口径：Skill = **AI 的大脑**，MCP = **AI 的工具箱**，yo-skill = **保险库**，Agent = **AI 助手**【5】。这一隐喻体系已被 Cherry Studio 官方文档独立验证（"应用商店 + 工具箱"类比）【1】，不是自嗨。

**铁律 3：渐进披露（Progressive Disclosure）。** 首屏只呈现"你现在能做什么"，技术细节全部折叠到二级界面；所有参数给 sensible defaults，只有触碰阈值时才打扰用户【3】。高级用户留逃生通道（查看/编辑原始 JSON），但入口深埋【3】。

## 二、产品信息架构

四屏一抽屉，多一个都不加。V2 的变化：主屏从两组扩为**三分组**（AI 助手 / 大脑 / 工具箱），商店升级为**分类仓库**。

```
yo-skill
├── 主屏「保险库」        # 默认落地页：AI 助手 + 大脑 + 工具箱三分组 + 全局搜索
│   ├── 分组：我的 AI 助手   # 已检测到的 Agent（版本 / 可更新 / 一键更新）
│   ├── 分组：我的大脑      # 已收拢的 Skill（跨 Agent 去重后聚合展示）
│   └── 分组：我的工具箱    # 已收拢的 MCP + 启停开关
├── 详情页「能力卡片」     # 三种卡片：助手卡片 / 大脑卡片 / 工具卡片
├── 仓库「发现」          # SkillHub 式分类仓库：分类导航 + 搜索 + 一键安装
├── 冲突解决页            # 仅在冲突/重复发生时出现，不占常驻导航
└── 设置抽屉             # 右上角齿轮，四层：通用 / 同步 / 安全 / 高级
```

判断依据：

- **主屏即保险库，不放仪表盘。** 1Password 的首屏是"你的东西列表"而不是统计图表；Mackup 用"应用维度"而非"文件维度"组织配置【2】【3】。小白要的是"我的 AI 会什么"，不是遥测数据。cc-switch 的用量统计/speedtest 明确不抄【4】。
- **AI 助手是主屏一等公民。** cc-switch 验证了"自动识别本机已装 Agent"是桌面管理器的地基能力【4】；但 cc-switch 把 Agent 当配置切换对象，yo-skill 把 Agent 当"被照顾的对象"——卡片上直接给版本状态和一键更新。
- **大脑/工具箱默认按"能力"聚合，不按 Agent 分组。** 同一个 Skill 装在 Claude Code 和 Codex 里，主屏只显示**一个条目**（角标注明"已教给 2 个助手"），这才是"统一管理"的可视化表达；需要时可切换"按助手查看"的次级视图。
- **全局搜索框置顶**（Raycast 范式）：搜索同时覆盖"已安装的"和"仓库里的"，用户不需要先想清楚去哪找【3】。
- **冲突/重复页非常驻**：冲突与重复是异常态不是功能。GitHub Desktop 也只在冲突发生时才呈现解决界面【3】。
- **导航项 ≤ 3**（保险库 / 发现 / 搜索框），设置收进抽屉。Linear 式分层【3】。

## 三、核心用户旅程（六条）

每条旅程标注「一键点」——用户唯一需要主动点击的位置。其余步骤全部自动。

### 旅程 1：首次启动 onboarding

1. 打开 yo-skill → 自动扫描本机已安装的 Agent（检测 `~/.claude/`、`~/.codex/` 及 CLI 版本）【1】【4】【6】
2. 展示发现结果："找到你的 2 个 AI 助手：Claude Code、Codex。它们现在会 12 个本事、有 5 件工具。"顺带提示："Claude Code 有新版本可更新。"
3. **一键点：「把它们装进保险库」** → 现有配置自动导入索引（auto-discovery 消除空白页焦虑【1】），**同时完成首次收拢去重扫描**：跨 Agent 重复安装的条目在结果页直接标出（见旅程 5）
4. 选择是否开启云同步：设置主密码 → 生成**恢复码**（强制保存，1Password Recovery Codes 范式【3】）→ 完成
5. 不开启云同步则直接进入主屏，本地模式功能完整（telemetry 默认 no-op 的离线友好原则【6】）

设计判断：**先给价值再要账号。** 把注册/密码放在"用户已经看到自己的东西被管好"之后，而不是开门就要登录（Notion/Arc onboarding 的共同教训是前置注册流失最高【3】）。

### 旅程 2：装一个"大脑"（Skill）

1. 主屏搜索框输入意图（如"写小红书文案"）→ 结果混排已安装 + 仓库条目
2. 点进能力卡片：一句话价值 + 能力徽章（见 §4.2）+ 来源星标数
3. **一键点：「教给 Claude Code」**（按钮自动带出目标 Agent，多 Agent 时是下拉多选——"同时教给哪些助手"）→ yo-skill 自动完成下载、安全扫描、写入所选 Agent 的 skills 目录、校验【2】
4. 卡片变为"已学会"状态；若所选 Agent 已有同名/相似条目，先走旅程 5 的重复处理而不是直接覆盖
5. 后续仓库出新版本时，卡片出现暖橙"有新版本"标记 → **一键点：「更新」**；得益于收拢管理，更新保险库里的单一条目即对所有已教给的助手同时生效（Setapp 统一更新范式【2】）

设计判断：**按钮文案是动词不是名词。** 不写"Install"写"教给 XX"——GitHub Desktop 把 `git rebase` 降维成按钮文案的同一手法【3】。安装方式的多样性（git clone / npx / plugin 命令）由产品内部消化，用户永远只见一个按钮【2】。

### 旅程 3：装一件"工具"（MCP）

1. 仓库浏览工具箱分类（按场景：写代码 / 查资料 / 处理文件，Setapp 式场景分类【2】）
2. 能力卡片写明：需要什么钥匙（API key）或不需要
3. **一键点：「放进工具箱」** → 自动安装运行时依赖（Node/uv，MCPHub Desktop 已验证可行【1】）→ 如需要钥匙，弹出保险库钥匙表单（集中凭据管理，用户不用去翻各平台文档找 env 名【1】）→ 自动写入所有已选 Agent 的配置并提示重启
4. 卡片出现启停开关（toggle 而非删配置，Cursor 范式【1】）
5. 工具同样支持"有新版本 → 一键更新"，更新前自动记录当前可用版本，更新失败一键回退（与旅程 6 助手更新同一安全网逻辑）

设计判断：**依赖和配置写入不闭环，就不配叫一键安装。** mcp.so 式"复制 JSON 自己粘贴"在 yo-skill 里只作为高级模式的备选入口存在【1】。

### 旅程 4：换电脑（核心付费场景）

1. 新电脑下载 yo-skill → 选"我有账号"→ 输主密码
2. **一键点：「恢复我的保险库」** → 拉取云端加密 vault、本地解密（E2E，云端只存密文【6】）
3. 自动检测新电脑的 Agent（未安装的给出"要不要顺便安装"的引导，见旅程 6）→ 把大脑和工具箱**一次性写入**各 Agent 配置目录 → 清单式结果："已恢复 12 个本事、5 件工具"
4. 旧设备显示在"已信任设备"列表，可远程移除（1Password 已信任设备审批范式【3】）

设计判断：**新设备恢复是整个产品的"啊哈时刻"，必须一次点击出结果清单。** chezmoi 把多步封装成一条命令的思路【2】，在 GUI 里就是一个按钮。

### 旅程 5：重复项收拢与冲突解决（异常态）

V2 把"重复"和"冲突"明确分开处理——两者技术上都走 6 维度检测【6】，但呈现给小白的语义完全不同：

**A. 重复（同一东西装了多份）**
- 触发：首次导入扫描、安装新条目、每次同步后
- 呈现：主屏温和提示"有 3 个本事重复了"，不弹窗不报警【3】
- 重复页：**分组列表**，每组显示"这份本事同时教给了 Claude Code 和 Codex"或"你的 Claude Code 里有两个很像的本事"
- **一键点：「合并成一份」** → 收拢为保险库中的单一条目（单一事实源），一处更新、对所有已选 Agent 生效；默认推荐项即"合并"（sensible defaults【3】）
- 不想合并可"保持现状"，该决定被记住、不再追问

**B. 冲突（同名但内容不同 / 两台电脑改乱了）**
1. 主屏提示："有 2 个本事两边不一样"
2. 冲突页：**左右并排卡片 + 差异高亮**（GitHub Desktop 范式【3】），注明"家里电脑 · 昨天改的" vs "公司电脑 · 今天改的"
3. **一键点：三选一——「留左边」「留右边」「两个都留（自动改名）」**
4. 选完全局生效，同步继续

设计判断：**重复给"合并"一个按钮，冲突才给"三选一"**——重复是低风险默认有正解，冲突是真需要人拍板。永不出现"合并冲突""resolve""dedupe"字样；语义级相似度在技术层计算，呈现层只给卡片。

### 旅程 6：装/更新一个"AI 助手"（Agent 本身）

1. 主屏"我的 AI 助手"分组：已检测到的 Agent 卡片显示当前版本；有新版本时卡片右上角出现暖橙圆点 + "有新版本"
2. **一键点：「更新」** → yo-skill 调用对应包管理器完成升级（npm 等），显示结果；更新前自动为该 Agent 的配置打快照，更新失败一键回退
3. 想装新 Agent：仓库"AI 助手"分类里列出支持的 Agent（MVP：Claude Code、Codex【6】）→ **一键点：「安装」** → 自动装运行时依赖 + 安装本体 + 安装完成即出现在主屏分组

设计判断：**Agent 更新是"照顾"不是"运维"。** 不做版本历史面板、不做 changelog 全文、不做降级选择器（深埋高级层）；小白只需要"有新版本 → 点一下 → 好了"。配置快照回退是安全网，因为 Agent 升级冲掉自定义配置是真实发生过的社区痛点【1】。

## 四、界面设计详述

### 4.1 主屏「保险库」

| 区域 | 内容 | 设计依据 |
|---|---|---|
| 顶部 | 全局搜索框（搜索已装 + 仓库） | Raycast 单一入口【3】 |
| 分组一 | **我的 AI 助手**：已检测 Agent 卡片（名称 / 版本 / 可更新标记 / 一键更新） | cc-switch 自动识别【4】 |
| 分组二 | **我的大脑**：收拢后的 Skill 卡片，**按能力聚合**（角标：已教给 N 个助手） | 统一管理的可视化表达 |
| 分组三 | **我的工具箱**：收拢后的 MCP 卡片 + 启停开关 | Cursor toggle 范式【1】 |
| 卡片信息 | 名字、一句话用途、装在哪个/哪些 Agent、启用状态 | 只答"是什么/在哪/开没开" |
| 右上 | 同步状态小圆点（绿=已同步/黄=待同步/灰=本地模式） | 非打扰式状态表达【3】 |
| 视图切换 | 默认"按本事看"，可切"按助手看"（次级） | 聚合优先，分组兜底 |

不在主屏放：统计数据、存储用量、日志入口。全部进设置抽屉。

### 4.2 详情页「能力卡片」（三种类型）

**通用结构**：头部（名称 + 一句话价值 + 能力徽章矩阵【2】）→ 中部（来源、更新日期、版本历史，每次修改带版本说明，Humanloop 范式【2】）→ **存放方式**（2026-08-12 用户定稿：所有助手共用一份【默认——实体放公共目录 `~/.agents/skills/`，认它的助手直接生效，不认的由 yo-skill 自动搭桥】/ 每个助手单独放一份【Cursor、云同步盘、权限受限环境的兼容性兜底】；单 Skill 可覆盖全局默认，用户话术不出现 symlink/junction/copy；竞品依据与工程纪律见 `../20260812_115055_skill_storage_strategy/`）→ 操作区（按状态的主按钮）→ 折叠区（默认收起：试运行、原始定义文件查看——高级用户逃生通道【3】）。

**能力徽章**（小白化安全标签，Awesome Claude Skills + SkillHub 安全扫描的合体【2】【7】）：
- 🔒 会联网 / 📁 会读你的文件 / 🔑 需要钥匙 / ✅ 自包含 / 🛡️ 已通过安全扫描

**三种卡片的操作区差异**：

| 卡片类型 | 主按钮 | 特有信息 |
|---|---|---|
| 大脑卡片 | 「教给 XX」/「有新版本 → 更新」/「已学会 → 移出保险库」 | 已教给哪些助手（多选增删） |
| 工具卡片 | 「放进工具箱」/「有新版本 → 更新」/ 启停 toggle | 需要的钥匙、运行状态 |
| 助手卡片 | 「更新」/「安装」 | 当前版本、管着多少本事和工具 |

### 4.3 仓库「发现」（SkillHub 式分类仓库）

V2 重点升级：从"精选列表"升级为**分类仓库**，交互范式对齐 SkillHub / skillhub.club / LobeHub 的已验证形态【7】：

- **分类导航**：场景分类（写作 / 编程 / 设计 / 办公 / 生活…）而非技术分类，每类卡片网格排列【7】
- **卡片字段**（对齐 SkillHub 卡片实证）：名称、一句话描述、作者、GitHub 星标数、🛡️ 安全扫描标记、**支持平台图标**（Claude Code / Codex 图标，小白一眼知道"我的助手能不能学"）【7】
- **列表排序**：默认"最受欢迎"（星标 + 安装量降选择焦虑【2】），可切换最新 / 评分
- **仓库内容来源**（MVP）：聚合公开 SKILL.md 目录（SkillHub 爬取模式：GitHub 仓库 `skills/`、`.claude/skills/`、`.codex/skills/` 等路径 + AGENTS.md 类 project context 文件【7】），先聚合后精选，不做开放作者入驻
- **一键安装**：卡片上直接放「教给 XX」按钮，不必先进详情页（SkillHub 列表页直接给 `npx skillhub install` 一键命令的对偶设计【7】）；也支持**分享链接** → 官网落地页「用 yo-skill 打开」→ `yoskill://` deeplink 唤起安装确认页（ChatWise/Raycast/cc-switch 三重验证【1】【2】【4】）

设计判断：**分类仓库的价值不在"多"，在"敢装"。** 星标 + 安全扫描 + 平台图标是给小白的三颗定心丸；ColaOS 调研的教训是"装 1 万个 Skill 反而让 Agent 效果变差"【6】，所以默认排序永远把头部精选顶在前面，不鼓励囤积。

### 4.4 设置抽屉（四层）

| 层 | 内容 | 默认值 |
|---|---|---|
| 通用 | 语言、主题（米白/墨黑随系统）【5】、**新装 Skill 存放方式全局默认**（所有助手共用一份 / 每个助手单独放一份） | 开箱即用；存放方式默认"共用一份" |
| 同步 | 开关云同步、已信任设备列表、立即同步按钮 | 同步频率自动，不暴露 |
| 安全 | 改主密码、恢复码、锁定时长 | 主密码 + 恢复码强制【3】 |
| 高级 | 冲突/重复检测敏感度、端口范围、原始 JSON 编辑、Agent 版本历史与降级、日志 | **全部默认折叠**【3】 |

### 4.5 新设备恢复页

见旅程 4。单独定义是因为它是付费转化的核心时刻：结果清单（"已恢复 12 个本事、5 件工具"）必须配成功态视觉，给用户"值了"的瞬间。

## 五、"一键操作"清单（验收标准）

每个一键都必须满足：一次点击、自动兜底、结果可见。

| # | 一键 | 点击后产品做什么 | 竞品依据 |
|---|---|---|---|
| 1 | 装进保险库 | 扫描 Agent 及其全部配置 → 导入索引 → 顺带做重复项扫描 | MCPHub auto-discovery【1】/ cc-switch【4】 |
| 2 | 教给 XX | 下载 + 安全扫描 + 写入所选 Agent 目录 + 校验 + 重复检查 | 统一安装入口【2】/ SkillHub【7】 |
| 3 | 放进工具箱 | 装依赖（Node/uv) + 收钥匙 + 写配置 + 提示重启 | MCPHub Desktop【1】 |

| 7 | 留左/留右/都留 | 应用冲突决策并继续同步 | GitHub Desktop【3】 |
| 8 | 更新 / 安装助手 | 包管理器升级或安装 Agent 本体，更新前打配置快照 | cc-switch 检测【4】 |

**反向约束**：任何需要用户打开终端、编辑文件、复制粘贴、查找路径的交互，都视为设计事故。

## 六、隐喻与文案体系

| 技术概念 | 界面用语 | 禁用写法 |
|---|---|---|
| Agent（Claude Code / Codex） | AI 助手 | agent、客户端、harness |
| Skill | 大脑、本事（"教 AI 一个本事"） | Skill、技能包、插件 |
| MCP server | 工具、工具箱（"给 AI 添件工具"） | MCP、server、服务 |
| Vault | 保险库 | vault、仓库、资产库 |
| API key / env | 钥匙 | env、环境变量、token |
| Sync | 同步（"随身带"） | 备份、上传、push |
| Install | 教给 / 放进 / 安装（仅 Agent 本体用"安装"） | Install、部署、配置 |
| Duplicate | 重复（"这个本事重复了"） | dedupe、冗余 |
| Update | 更新（"有新版本"） | upgrade、迁移 |

- 一句话定位（已定稿【5】）：**"让 AI 学会新本事，跨电脑随身带"**
- 空状态文案示例："你的 AI 还没学会任何本事，去**发现**逛逛？"
- 收拢文案示例："这个本事在两个助手里各装了一份，**合并成一份**以后一处更新两边都新。"
- 错误文案原则：说人话 + 给出路。"这件工具需要一把钥匙"而非"env var missing"【3】
- 视觉规范沿用品牌定稿【5】：薄荷绿 `#00D4A8`（主行动色/成功态）、暖橙 `#FF8C42`（提醒：可更新 / 重复 / 冲突）、墨黑 `#0F1419`、米白 `#FAF8F5`；中文思源黑体、英文 Inter。暖橙只用于需要用户注意的场景，重复页和冲突页都不是错误页。

## 七、小白卡点 → 对策总表（调研闭环）

| 竞品实证卡点【1】【2】【7】 | yo-skill 对策 |
|---|---|
| 安装命令格式五花八门，不知用哪条 | 自动识别 Agent，界面只有一个按钮 |
| 要手写/粘贴 JSON，语法错全挂 | GUI 表单为主，JSON 深埋高级层 |
| 找不到配置文件路径 | 产品自动写入，路径概念不出现 |
| 缺 Node/uv 依赖装不上 | 一键装依赖，失败给中文人话提示 |
| 不知道要不要 API key、去哪找 | 卡片前置"需要钥匙"徽章 + 保险库统一收钥匙 |
| 开关一个 server 要反复改文件 | toggle 开关，配置永驻 |
| 同一个 Skill 在多个 Agent 各装一份，改了一处忘了另一处 | 收拢合并：单一条目，一处更新多处生效 |
| Agent CLI 版本过旧不自知，升级怕冲掉配置 | 主屏版本标记 + 一键更新 + 更新前自动快照可回退 |
| 市场条目太多不敢装 | 星标 + 安全扫描 + 平台图标三颗定心丸，精选排序置顶 |
| 换新电脑一切重来 | 旅程 4 一键恢复 + 结果清单 |
| 安全权限看不懂 | 能力徽章矩阵（联网/读文件/要钥匙/自包含/已扫描） |
| 概念分不清（Agent / Skill / MCP / Plugin） | 只有"助手 / 大脑 / 工具箱"三个概念 |
